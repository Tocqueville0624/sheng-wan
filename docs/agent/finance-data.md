# Finance data pipeline

Thales’ Olive has reviewed business-category adapters for AAPL, MSFT, GOOGL, AMZN, META, NVDA, and TSM. Its versioned S&P 500 catalog also supports on-demand financial imports, including business revenue from a coherent reported statement table. A selectable catalog entry is not a promise of complete chart coverage. All public data must be real, automatically extracted, source-linked, and reconciled. Never publish synthetic fixtures or silently substitute estimated business splits.

## Refresh and discovery

- `pnpm data:update` discovers current SEC filings through Submissions, downloads the latest annual filing and three quarterly filings per company, and validates everything before an atomic snapshot replacement.
- The legacy v1 API keeps its three-annual/six-quarterly snapshot. The website and v2 API use `finance-history.json`: all seven featured companies have ten annual and twenty verified quarterly periods (210 total), including when storage is unavailable or contains an older short snapshot. `pnpm data:save-history` captures completed online data, validates every featured company, and atomically replaces this deployment fallback; it never enqueues refreshes. Online v2 imports target the same depth. Periods may not be consecutive: missing Q4 values are not fabricated; coverage notes and CSV disclose the available history. Reviewed business history retains its existing chart. Basic-only or mixed-coverage histories also show exportable consolidated revenue/net-income bars; every selected period gets either a reconciled profit flow or independent signed metric bars. Lack of business splits never means lack of a usable chart.
- `sec-shared.ts` shares issuer/path validation, bounded response reading and declared identification between the CLI and Worker. Both keep at least 550 ms between sequential requests. The authorized public contact is sent only in the User-Agent to HTTPS `sec.gov`; redirects are not followed. Never forward that email to the FX source.
- Submissions indexes expire after one hour; immutable filing documents are cached in ignored `.cache/finance/sec/`. `--force` bypasses this cache. Future filing dates and report dates after filing dates are excluded.
- A reviewed filing adapter must extract the filing's **current** report period, not merely valid comparative columns. Missing dimensions, changed taxonomy, unavailable sources, conflicting precise facts, or invalid balances withhold that candidate; v2 retains prior valid periods while other candidates progress. The all-company CLI snapshot still publishes only when its complete validation passes.
- SEC Company Facts supplies basic consolidated metrics, not business breakdowns. Its non-dimensional standard-taxonomy scope cannot replace filing adapters. See [SEC API scope](https://www.sec.gov/search-filings/edgar-application-programming-interfaces). Reviewed business categories still come from archived filings.
- Original separate XML reports use `standalone-source-index.ts` to discover actual same-accession attachment names, and `standalone-revenue-reader.ts` to join unmodified physical HTML cells to original XML scopes and declarations. Stored proofs retain original resource fragments and fiscal geometry; the shared validator decodes those declarations again instead of trusting copied monetary values. Known source-year/layout rules for ALB and AME supplement the offline audit, preserving all prior metrics, dates, currencies and sources. AME's FY2016 closing business table remains distinct from its differently reported MD&A values. These rules do not claim support for unknown future layouts or first imports without financial candidates. Worker queue integration and real online import acceptance remain required before declaring this path publicly available.
- `pnpm data:corpus -- --all --register-cached-attachments` records physically cached original indexes/XML in the existing acquisition inventory without fetching or approving financial facts. Offline audits require each source's acquired SHA-256 and byte count to match; unregistered bodies and changed fingerprints are withheld. New corpus downloads acquire actual indexed XML names for standalone reports. Raw bodies and corpus reports remain local-only; attachment acquisition, financial parsing, full retained-history coverage and live browser acceptance are separate checks.
- `business-v2.ts` supplements generic imports from the same archived inline filing, independent of whether the consolidated profit flow is already available. A complete, consecutive revenue section must end in the existing reported consolidated revenue fact. All rows use the same period, currency and classification: either nondimensional named revenue lines, or exactly one supported product/service or reportable-business axis. Typed contexts, geographic axes, mixed axes, negative branches, conflicting facts and incomplete totals are withheld. Source order and visible table labels establish the partition; never use arbitrary subset-sum combinations or generated labels to make figures fit.
- `facts-v2.ts` selects needed concepts before JSON parsing, groups facts by accession/dates/currency, and preserves field-level sources. Fiscal-year metadata is applied only to the filing's current report end. Earlier comparative columns recover fiscal labels from that filing's known period and a matching annual cycle, including 52/53-week calendars; their values and accession remain unchanged. Q4 differences require the same accession, start, currency and concept; no cross-filing subtraction. Financial-sector customer-contract revenue is not treated as total revenue. Missing values stay absent and negative income remains negative.
- Annual duration does not make a quarterly trailing-twelve-month disclosure a fiscal year. SEC IFRS concepts may have null human labels; use the exact taxonomy identifier as the source label. For basic imports with incompatible cost scopes or unmodeled adjustments, withhold cost/gross-profit/operating-expense metrics together and preserve independently sourced revenue and income with a coverage warning; never force a flow to balance. Conflicting copies of a fact exclude that accession/date/currency candidate without blocking valid candidates from other filings.
- Generic standard-taxonomy cost concepts can describe a subset of activity: McDonald's `CostOfGoodsAndServicesSold` can mean franchise occupancy expense. Revenue minus an unreviewed cost tag is not sufficient evidence of consolidated gross profit. Such derived gross profit requires an independently reported operating-expense subtotal that corroborates it. `normalizeBasicCompany` applies the same rule to old stored imports on reads, without crawling or rewriting the stored source; directly reported gross profit and reviewed adapters remain intact.
- Consolidated statements without a gross-profit subtotal can use a direct revenue → total operating costs / operating income flow. `CostsAndExpenses` must reconcile with revenue and operating income; gross profit is never invented. Generic imports inspect up to 30 selected filings to supplement standard facts with exact, non-dimensional inline facts. No label guessing or pretax-from-net-income substitution.
- `statement-v2.ts` reads the filing's primary income-statement table for generic issuers: rows in source order, one precise non-dimensional fact per row, visible labels (trailing footnote markers removed). Standard concepts anchor revenue (the period's existing tag and amount), operating income, income tax and net income. The row directly above tax is pretax profit, including issuer extensions such as ORCL's. After tax, rows are walked in order: subtotals must equal the running amount (issuer extensions only when exact), reviewed after-tax equity-method, discontinued-operation and noncontrolling-interest concepts change it by their signed reported values, and the parent net-income row must equal the result; any other line withholds the reading. Several lines of one kind are summed as a calculated value; reported zeros add no flow. MCD's net-income cell carries an equity-statement member; the identical non-dimensional fact is used.
- Source-current gross-profit statements can start with a revenue-only private candidate. A directly reported consolidated gross-profit row completes the gross stage; missing cost and operating-item totals may be calculated only as the exact differences of the corresponding reported subtotals, with both input concepts and source URLs recorded. A conflicting reported cost or expense total withholds recovery. Expenses are split only when nonnegative original rows exactly partition the total. Mixed signed items or incomplete/rounded detail remain one explicitly labeled "Operating expenses and other items (net)" node; R&D/SG&A values are never turned into a residual expense partition of that net node. Original values and strict graph identities remain unchanged.
- Separately reported gross/operating and final after-tax subtotals can carry explicit signed source-rounding flows. Every participating metric must retain reported same-filing provenance and declared inline precision; the magnitude fits the combined half-unit intervals and remains at most 0.1% of revenue. This is not a wider accounting tolerance. Reported totals stay unchanged and exact graph conservation includes the separately labeled flow. GE HealthCare's comparative 2024-Q2 and 2024-Q3 fixtures exercise these two different stages.
- An intermediate standard consolidated-income subtotal immediately after tax may corroborate pretax minus tax within its own declared precision. Record its original amount/tag/precision, keep the exact running arithmetic, and independently reconcile the final parent amount. Unknown extension subtotals still require exact equality. GE HealthCare 2026-Q2 reports consolidated income of $573M while pretax minus tax is $574M; its $561M parent income reconciles exactly after $13M of noncontrolling income.
- When a reported operating-expense total and the two standard R&D/SG&A rows differ within their combined precision, retain all three actual values and the source components as proof. Draw the reported total without an inferred remainder or rescaled component branches; preserve the components and discrepancy in SVG metadata/CSV. This is separate from a calculated net operating-items subtotal. Missing precision, changed component tags/amounts, foreign provenance or excessive differences withhold the flow.
- Costs: without a gross-profit row, the final row above operating income is the reported total when revenue − it = operating income (declared-precision rounding is disclosed); otherwise the listed rows must be nonnegative and exactly partition revenue − operating income, and their sum is a calculated total. Statements without an operating-income line (IBM, JNJ, TJX and many others) chart revenue or reported gross profit → "expenses and other items (net)" → pretax profit; that node is the reported total row when one equals the difference, otherwise the calculated difference of the two reported subtotals, and non-operating items are never shown separately. `operatingCostDetails` / `operatingExpenseDetails` are drawn only when their rows exactly sum to the parent. Existing reported values are never replaced; any conflict leaves the period unchanged.
- `pnpm data:coverage -- --sample` (or tickers; `--max-filings N`, `--offline`) replays the generic Worker import against SEC sources without storage writes and compares with the previous engine; reports are written to ignored `.cache/finance/coverage/`.
- Full-catalog acquisition, offline review and acceptance are documented in [finance-corpus.md](finance-corpus.md). Raw acquisition and complete business/flow parsing are separate statuses. Reviewed WMT/JNJ tables preserve reported classifications, actual corporate income and exact dimensions; no residual is assigned to a business.
- External net sales can supply a generic business partition only when the complete original row, aligned business headers and exact scopes reconcile to consolidated revenue. IDEX's separately reviewed external-customer columns preserve its three original business contexts, both nondimensional total copies and the untagged elimination dash. An independent primary net-sales row corroborates the total. Gross and internal sales rows never fill missing external amounts; unknown headers, dimensions, monetary columns, conflicting copies or changed proof withhold the partition. Read validation and SVG/CSV retain the source coordinates and complete column accounting.
- `operating-v2.ts` reads a complete primary operating ledger only under reviewed issuer rules. APD's operating gains/losses remain signed, separate from the exact sum of its reported costs. CRL's service and product costs retain their two exclusive product/service contexts; consolidated revenue and operating-income anchors remain nondimensional. Every intervening fact must have a reviewed meaning and the complete ledger must reconcile exactly. Unknown tags/scopes, conflicting values or changed proof withhold the profit flow while independently validated business revenue remains available. `operatingItems` preserves original rows, concepts, dimensions, signs, precision and same-filing provenance in SVG metadata and CSV; no gross profit or residual expense is invented.
- SPGI, CARR and PLD have reviewed primary operating ledgers with explicit cost subtotals. Every cost and gain row is accounted for in source order; subtotal rows corroborate the cost sum and are never added twice. PLD's intermediate operating-income-before-property-gains row is independently verified. Carrier's product/service costs keep their exclusive dimensions. The reviewed ledgers use the primary table's own fact references; changed tags, unknown rows or conflicting anchors withhold the candidate. Prologis can exclude a Company Facts operating-expense metric only when the same original value is proved to be a separate segment-NOI expense subtotal: total revenue plus its signed expenses must equal the explicitly dimensioned operating-segment subtotal, which differs from consolidated operating income. Preserve that original metric source, amount, precision, labels, dimensions and table coordinates in `excludedSegmentExpenses` metadata/CSV; never reinterpret or negate it as a consolidated cost.

- `direct-net-v2.ts` supports ARE's reviewed primary statements without reported operating-income, pretax or tax rows. Every expense row and subsequent signed gain is retained and reconciled with reported total expenses and consolidated net income, then NCI/parent/common-shareholder allocations. `totalExpenses` includes interest and is never labeled operating costs. The same-filing `CostsAndExpenses` basic candidate is reclassified only when its exact amount/provenance match this ledger. Missing stages stay absent; unknown concepts, dimensions, conflicts or unexplained gaps withhold this flow. Original expense components, signs, precision and source order survive in SVG metadata and CSV as `directNetItems`.
- `operating-net-v2.ts` supports DLR's primary statements without a pretax subtotal. Every original operating cost, optional operating-income-before-property-gains subtotal, property gain, subsequent signed equity/other/debt item, interest and tax row must reconcile exactly to consolidated, parent and common-shareholder income. Negative operating costs are separate reversals; source-order tax/debt differences remain in the proof. `operatingNetItems` preserves original rows, concepts, signs, precision and provenance in SVG metadata/CSV. Independently reported tax-note pretax metrics remain independent and are never substituted for an absent primary row. Exact `OperatingExpenses` primary totals are reclassified as total operating costs only with matching prior amount/tag/provenance. Preferred redemption gains retain their original signed value and explicitly additive effect; other ownership allocations are deducted once. Unknown concepts/scopes and changed anchors withhold the candidate.
- `gross-operating-v2.ts` reads Flex's reviewed primary gross/operating ledger. Original sales cost and cost-of-sales restructuring remain separate and reconcile to reported gross profit. Signed operating costs retain their source order; positive expense lines form their actual sum, while a reported negative restructuring cost appears separately as a reversal. `grossOperatingItems` retains original concepts, amounts, labels, precision, table rows and same-filing provenance in metadata/CSV. Only the primary table's own facts participate: a more precise narrative copy cannot replace its displayed amount, even with an identical QName/context. A source refresh also re-reads an existing calculated ledger from those actual cells; conflicting independently reported anchors remain withheld, and obsolete rounding is removed only when the new original primary sum is exact. Any operating source-rounding difference requires all original component/subtotal precisions and the existing 0.1% limit; no aggregate precision or unreported expense is invented. Annual ITS/RMS/CPI contexts and quarterly ITS/RMS/CPI contexts are separately reviewed; historical FAS/FRS classifications remain distinct, including an explicitly tagged corporate zero. A blank dash is never converted to a zero fact.
- Separately reported continuing and discontinued noncontrolling income may replace a Company Facts continuing-only metric with their exact consolidated sum, only when both distinct source concepts and the prior component match the same filing. Already reported consolidated NCI is never replaced by a contradictory sum.
- Mondelez's reviewed `EquityMethodInvestmentRealizedGainLossOnTransaction` row (including its reviewed historical lowercase `on` spelling) is an after-tax transaction item, separate from ordinary equity-method earnings. Its original signed value is added once: a Loss caption never reverses a negative fact. The exact, consecutive primary-table chain from pretax and tax through transaction, equity income, consolidated income, NCI and parent income is preserved in `afterTaxTransactionItems`. A finite issuer/concept rule, same-filing metric provenance, original precision and both exact income identities are required; changed stages, scopes, concepts or conflicting amounts withhold the flow. Reviewed captions that include impairments retain that scope in the chart label. Reported zero remains in metadata/CSV and adds no ribbon. Original annual and quarterly sources exercise positive, negative and zero transactions; no residual or rounding amount is introduced to balance this chain.
- Numeric inline facts can have one nested `nonFraction` child under Inline XBRL 1.1 §10. Matching transformation, scale and unit are required; use its lexical value and retain each fact's own sign, context and precision. Multiple children, mixed numeric markup and mismatched properties remain unsupported. Original APD FY2021 markup tests the nested annual/quarterly facility-closure loss; the number is never scaled or negated twice.
- Financial-sector catalog membership alone does not identify a bank. SEC Submissions SIC 73xx confirms business services (for example Visa's 7389), allowing customer-contract revenue when a broader total-revenue concept is absent. Traditional financial SICs and unknown classifications still exclude fee/contract revenue as a substitute for total revenue and disclose the resulting coverage limit.

## Source adapters and semantics

- `adapters.ts` contains reviewed QName/axis/member rules and reference filing URLs, never financial values. Runtime URLs come from current Submissions discovery. Exact dimension sets prevent subtotal/child double counting.
- Generic business extraction uses original visible statement labels plus exact revenue QName, dimensions, declared precision and issuer/filing/date/currency provenance for every branch. An explicitly labeled subtotal is omitted only when a unique contiguous preceding group reconciles at source precision; its reported amount and source identity remain recorded. For example Tesla's automotive subtotal is not added to its component revenue rows. The first complete statement-table partition wins; later geographic or more detailed tables are not mixed into it. Actual MCD, TSLA and IBM source excerpts cover nondimensional revenue categories, a product subtotal, and an independent third issuer in regression tests.
- Reviewed 3M three-business tables use each filing's actual Corporate or Corporate and Other caption and standard corporate scope. Its primary statement can corroborate the same revenue amount under another standard revenue concept only when a unique same-amount source row and the full subsequent accounting chain pass; stored business proof is re-read after the concept changes. Source `IncomeLossFromSubsidiariesNetOfTax` is preserved as separate after-tax unconsolidated subsidiary income, never relabeled equity-method income or operating expense. After minority attribution, discontinued income is accepted only with an explicit ReportingEntity concept; continuing subtotals must equal the running amount. Negative corporate revenue, older four-business classifications and loss flows still require separate support.
- Abbott's reviewed annual and quarterly tables preserve their respective business captions and separately reported Other revenue under the corporate scope. Segment rows also contain costs and income: only the reviewed revenue QName enters the business partition. Subtotals are not counted twice; absent corporate amounts and changed classifications are withheld rather than filled from a residual.
- `product-portfolio-v2.ts` reads AbbVie’s complete original product section, including its footer-only page continuation. Each finite original product and portfolio member, temporal/year header, geographical/collaboration component and reported product total is checked; a product total includes collaboration revenue once. Portfolio sums are explicitly calculated from original product leaves, not mislabeled reported portfolio subtotals. The original reported All other amount is retained; blanks stay absent, and a misdated tagged zero withholds the partition. An independent primary net-revenue row corroborates the complete section. `productPortfolios` keeps actual cells, scopes, declarations, headers, coordinates and hierarchy; calculated branch inputs survive read validation and SVG/CSV exports. Changed names, dates, units, classifications, incomplete sections or conflicting facts are withheld. Old separate-XBRL and incomplete standalone Q4 sources remain separate gaps.
- `service-revenue-v2.ts` reads Akamai's complete original service-revenue tables under six finite caption/member profiles. The original sales-channel axis is permitted only by this issuer rule, never globally. Source year spans and single-quarter captions select the actual column; all comparative/YTD cells remain in `serviceRevenueRows`. Closing total and independent primary revenue must agree exactly with all original branches. Primary aggregate ReportableSegmentMember and nested aggregate/nondimensional declarations retain their distinct original contexts. Unreported business cost or gross profit stays absent. Unknown classifications, missing rows, changed dates/precision/units and conflicting copies withhold the partition; no residual or rescaled branch is created.
- `albemarle-business-v2.ts` reads Albemarle's individually reviewed, complete original business sections. Historical Lithium/Bromine/Catalysts/All Other/Corporate classifications and later Energy Storage/Specialties/Ketjen classifications retain their exact labels and dimensions. A reported segment subtotal corroborates the preceding businesses and is never added twice; All Other and Corporate remain separate reported branches. The entire physical table, comparative and YTD columns, original zero formats and independent primary net-sales/tax anchors are preserved in `albemarleRevenue`. Unknown classifications have no generic partition fallback for this issuer. Blank amounts remain absent and business gross profit is never estimated. Separate-XBRL historical sources still need a separately validated source reader; downloading them does not establish parsing coverage.
- One immutable Albemarle 2022 annual filing incorrectly declares fiscal-year metadata as 2021 while its cover, dated contexts and primary columns report 2022. `fiscal-label.ts` corrects only this reviewed issuer/accession/source and two inspected stored-source variants. Dates, amounts and field-level financial sources are unchanged; the original metadata stays in the business proof and a source-linked warning explains the correction. A fresh import must retain the actual 2021 period alongside the corrected 2022 period. Never infer a general calendar-year correction from this exception.
- `ixbrl.ts` parses bounded context/unit/numeric fragments instead of allocating an entire HTML tree. It matches entity CIK, duration, currency, taxonomy, units, scale, sign, and dimensions. It prefers the highest declared XBRL precision over rounded narrative repeats and rejects conflicting equally precise facts. Unsupported mixed numeric markup is withheld.
- AAPL: product/service categories, not geographic reportable segments. Preserve reported GAAP tax charges; do not substitute adjusted profit.
- MSFT: three reportable operating segments under the cited filing's comparative classification.
- Optional business gross profit is extracted only from a reviewed gross-profit or cost concept with exactly the revenue category's issuer, filing, dates, currency and dimensions. Generic dimensional categories accept reported `GrossProfit` or revenue minus reported `CostOfRevenue`; nondimensional custom revenue categories do not inherit a consolidated cost. Apple discloses Services cost and aggregate Products cost; the latter must never be allocated to iPhone, Mac, iPad or Wearables. Microsoft discloses cost for its three displayed reportable segments. Missing category cost/gross profit stays absent; operating profit is not gross profit. `grossProfitSource` retains the original reported input, exact tag/dimensions and filing identity so saved values and FX conversion can be revalidated. Same-statement legacy merges retain a missing optional source/value pair only when all other statement facts and provenance are identical.
- GOOGL: disaggregated Google Services categories, Cloud, and Other Bets; actual signed hedging is separate `revenueAdjustments`, never assigned to a business.
- AMZN: seven product/service groups. Five named operating costs come from direct tags; Technology and Infrastructure is not mislabeled R&D. Actual after-tax equity-method income/loss is `metrics.equityMethodIncome`.
- META: Family of Apps and Reality Labs.
- NVDA: prior filings report five specialized markets; FY2027 introduced Data Center and Edge Computing. Use each period's actual `segmentBasis`; do not invent a historical Edge Computing series.
- TSM: six customer platforms from native-TWD 20-F inline XBRL. Quarterly financials are exact 6-K HTML statement tables, parsed by `tsm-html.ts`; rounded platform percentages are never multiplied into invented amounts. Discover financial-statement 6-K filings and their consolidated-report exhibit, excluding annual December reports from the quarterly path.
- TSM basic Company Facts selects native TWD only; do not mix in convenience USD amounts. Older audited 20-F HTML tables provide explicitly labeled native-TWD comparative years; the convenience USD column is excluded. Online 6-K discovery follows the cover's described consolidated financial exhibit, deduplicates repeated links and verifies the report date against the statement. Older indexes may use the filing date as `reportDate`; only an explicit exhibit description can replace it. Legacy May/August/November filings are bounded discovery candidates, never presumed quarterly reports. Period-average FX conversion applies to every amount and separately reported adjustment.
- TSM's older statements explicitly report realized/unrealized gross profit on sales to associates. Preserve these signed `grossProfitAdjustments`, labels and source URLs; revenue minus reported cost plus the reported adjustments must equal gross profit. Never infer an adjustment as a balancing residual. Such periods retain their actual metrics and business breakdown when available, but the current positive-flow Sankey is withheld. Source details and CSV disclose the adjustments.
- TSM operating expenses are net of reported other operating income. Do not label a gross SG&A amount as a component when it would exceed that net total. Gross/cost arithmetic and net operating costs remain explicit.

## Signed accounting and shareholder income

- A reported negative gross, operating, pretax or net subtotal can form a signed accounting diagram when all original identities reconcile. Negative subtotals retain their signs and represent expense shortfalls; their ribbons may run toward earlier costs. Every magnitude and business branch uses one dollars-to-width scale. No loss is shown as extra revenue or cash, and no unreported gross profit, tax, cost or business category is filled in.
- `shareholder-v2.ts` reads original source-ordered allocations after an independently reported parent or consolidated income subtotal. The original `metrics.netIncome` remains unchanged. Reported minority income (only after a consolidated base), convertible preferred dividends and separately reviewed participating-security allocations may lead to the explicitly reported common-shareholder subtotal when the identity is exact. Never deduct minority income a second time after a parent base. Add the bridge only after the complete flow validates; a supported ownership subtotal must not invalidate an incomplete statement and discard its independently validated business partition.
- A primary diluted subtotal is not interchangeable with parent income. HPE's source can corroborate its same-amount subtotal only with an independently reported nondimensional standard parent-income fact for the same filing, dates and currency. `shareholderBridge` retains both tags, scope, original labels, amounts, precision and allocations, and is revalidated on use. Unknown allocation concepts, mismatched provenance and a missing corroboration withhold the bridge. Financial statements without tax or an appropriate operating route remain separately unsupported; no zero tax or pretax subtotal is manufactured.
- SVG/PNG and the exact-value table retain signed loss and common-shareholder amounts; CSV includes the common-income amount and full ownership proof. Original MRNA, AXON, F and HPE source excerpts cover loss-to-profit transitions, positive tax expense, tax benefits, minority attribution and preferred dividends in unit and desktop/mobile browser checks. INTC and BDX original primary tables exercise cost-detail routing and negative source rounding. Expense detail ribbons must not intersect an unrelated net-loss or rounding node. These checks are separate from full-corpus coverage and real SEC-backed Worker import acceptance.

## Reconciliation contract

- `FinancialPeriod.segments` requires stable IDs, labels, nonnegative actual revenue, `segmentSourceUrl`, and `segmentBasis` for every public period.
- Signed `revenueAdjustments` contain explicitly reported items or the narrowly validated source-rounding case below. Sum of business categories **plus** adjustments equals consolidated revenue.
- A generic business partition may preserve a signed `Source rounding` adjustment only when every branch and the consolidated total carry declared inline precision. Its magnitude must fit the combined half-unit precision intervals and be at most 0.1% of revenue. Original branch values are never normalized or rescaled. `businessBreakdownSource` and each `revenueSource` preserve the proof; `businessPeriod` revalidates it on use. Business revenue coverage is independent of gross profit or a complete operating statement, so a real breakdown can be shown even when a profit flow is unavailable.
- Revenue − cost + explicitly reported gross-profit adjustments = gross profit; gross profit − operating expenses = operating profit; pretax profit − income tax + after-tax equity-method income + discontinued operations = net profit (before noncontrolling-interest attribution).
- When US-GAAP `NetIncomeLoss` reports profit attributable to the parent, subtract separately reported `NetIncomeLossAttributableToNoncontrollingInterest` after tax and show the attribution separately. Preserve its sign and the original parent-income value (for example TSLA); it is profit allocation, not an operating expense. `ProfitLoss` already includes noncontrolling interests and must not have this attribution subtracted again.
- Optional `operatingExpenseDetails` are the complete original named nonnegative primary rows summing to operating expenses, including a sole reported expense row. They replace independent R&D/SG&A metrics in drawing and in the component-overflow check: those metrics may overlap and remain available independently. Altered amounts, duplicate IDs and missing labels withhold the partition. Original tags, amounts and precision survive in SVG metadata and CSV; direct total-cost routes keep their separate scope.
- `validate.ts` checks finite values, positive total revenue, dates, IDs, provenance, and identities. Tolerance is only `max($0.000001, revenue × 1e-9)`. Never rescale flows or create an unexplained balancing item.
- Direct operating flows may explicitly show `Source rounding` only when the three reported inline inputs carry declared XBRL decimal precision for the same accession, dates and currency. The difference must fit their combined half-unit precision intervals and be at most 0.1% of revenue. Original metrics remain unchanged; the signed reconciliation is separately disclosed in the diagram, exact-value table and exports. Missing precision or larger differences withhold the flow. Chart geometry still conserves amounts under the strict tolerance above.
- TSM uses the actual Federal Reserve H.10 period-average TWD-per-USD rate for **every** amount and category. The parser supports current DD-MON-YY dates and rejects incomplete period coverage. The rate source uses a non-email User-Agent.
- Fiscal dates are derived from filing metadata and actual statement dates, not the filing year attached to an older comparative fact. `updatedAt` means successful assembly time, not the fiscal period.

## Public API, storage, and operations

- Source-validated normalized snapshots can also be delivered as static JSON assets. `pnpm data:save-reviewed -- --ticker TICKER --input ACTUAL_RESPONSE --source-proof SOURCE_RESULTS --browser-proof BROWSER_RESULTS` requires a completed actual SEC task plus current annual/quarterly source and rendered/export evidence. It saves only normalized public financial facts under `src/data/generated/finance-reviewed/`; raw acquired filings remain private. The original source-check timestamp and a SHA-256-pinned asset index are retained. The Worker checks the asset hash, issuer and full v2 schema before supplementing reads, including when storage or SEC retrieval is unavailable. Coherent saved and newer validated statements retain the existing merge rules; quota, source spacing and POST behavior are unchanged. The response exposes `savedSourceSnapshot` provenance and preserves actual task errors. Hash failures fall back to the prior stored data. Static assets scale separately from the Worker bundle; visits never crawl SEC.

- A transient archived-filing HTTP 429, 5xx or timeout retains its cursor and participates in the shared 30/60-second alarm backoff. After three unsuccessful attempts, record the source gap and continue other history. Permanent failures are not repeatedly retried. Verified saved data and daily work limits remain in force. Both generic and featured-company filing paths use this bounded behavior.

- `GET /api/finance/snapshot` returns the complete validated manifest with ETag/cache headers; company-list and per-company endpoints remain available.
- The v1 API remains compatible. It refuses demo/corrupt/incomplete KV snapshots and falls back to a verified prior/bundled snapshot. The current frontend uses per-company v2 responses and initially serializes only Apple, not all seven companies or base64 logos.
- `assertPublishableManifest` is pure and shared with the frontend; it requires verified/delayed provenance, annual and quarterly coverage, and business breakdowns. Generic validators still support isolated test fixtures.
- `refreshSnapshot` writes only after full validation and preserves the true previous manifest for rollback. The local JSON is written to a sibling temporary file and atomically renamed.
- `--publish` is an explicit separate action: write versioned KV object, preserve `finance:previous`, then advance `finance:current`. Publication errors leave the local bundle unchanged. Do not publish without authorization.
- The GitHub workflow refreshes/tests and saves an artifact. KV publishing requires opt-in `FINANCE_PUBLISH=true` plus Cloudflare secrets; it is not deployed or enabled merely because configuration exists.
- The old synthetic generator was removed. `--curated` is disabled; reviewed Apple constants remain only as regression-test reference data and are never overlaid into production.
- Visits and catalog searches never trigger SEC crawling, a paid API, or an LLM. Only the public refresh/import button enqueues work. Keep source mappings and tests current when a company's reporting taxonomy changes.

## Online v2 contract

- `GET /api/finance/v2/catalog`, `GET /companies/:ticker`, `POST /companies/:ticker/refresh`, `GET /jobs/:id`. All are under `/api/finance/v2`; no client-supplied source URL is accepted. Cross-origin browser POSTs are rejected. Source errors and retry times are explicit.
- `FINANCE_STORE` is one SQLite-backed Durable Object. Its persistent FIFO-with-round-robin-steps queue serializes SEC requests globally.
